# الأمان

<Badge type="tip" text="جديد في 2.0" /> يشحن Lingua 2.0 مع مرحلة تصليب
شاملة F1–F9. تُوثِّق هذه الصفحة كل حارس، وكيفية تهيئته، وقائمة التحقق
النهائية للإنتاج.

## الحراس: F1–F9

| الحارس | المرجع | الوصف |
|---|---|---|
| **F1** مُعقِّم XSS | `HtmlSanitizer` | يُعقِّم قيم الترجمة من النوع `html` باستخدام قائمة وسوم/سمات مسموح بها قبل الكتابة. |
| **F2** رفض حقن SQL | `TranslationQuery` | يمنع استخدام تعابير JSON SQL الخام (`JSON_KEYS`، `json_object_keys`، `OPENJSON`) في شروط الاستعلام. |
| **F3** حماية اجتياز المسارات | `PathGuard` | يُطبِّع مسارات ملفات `lang/` ويرفض أي مسار يهرب من `lang_dir`. |
| **F4** قائمة بيضاء للغة المستهدفة | `TargetLocaleMiddleware` | يُعقِّم معامل اللغة قبل معالجته، يقبل فقط اللغات المثبَّلة الموثوقة. |
| **F5** حماية مورّد | `VendorTranslationProtectedException` | يمنع حذف/استبدال سلاسل الحزم التابعة لجهات خارجية عبر `forgetTranslation()`. |
| **F6** رفض بدل | `ImportValidator` | يرفض مفاتيح بدل (`*`، `%`) في البيانات المستوردة. |
| **F7** حماية من ReDoS | تعبيرات منتظمة ثابتة | جميع التعبيرات المنتظمة تستخدم أنماطاً ثابتة آمنة من ReDoS بدلاً من مُنشآت من مدخلات المستخدم. |
| **F8** إخفاء الأخطاء | معالج استثناءات مُخصَّص | تتسرب الاستثناءات الداخلية كأخطاء عامة 500 فقط؛ تتسجَّل التفاصيل محلياً لكنها لا تُوجَّه إلى الاستجابة. |
| **F9** بوابة المصادقة | `gate` / وسيط | مسارات الإدارة محمية بـ `['web', 'auth']` افتراضياً + اختياري `can:{gate}` قابل للتهيئة. |

## المصادقة والتفويض {#authentication}

**افتراضياً، الوصول يتطلب تسجيل الدخول:**

```php
// config/lingua.php
'middleware' => ['web', 'auth'],
```

بهذا الإعداد، يحتاج أي مستخدم مجهول الهوية إلى تسجيل الدخول قبل رؤية
أي صفحة إدارة في Lingua.

**للوصول القائم على الأدوار** عبر بوابة تفويض:

```env
LINGUA_GATE=manage-translations
```

```php
// app/Providers/AppServiceProvider.php
Gate::define('manage-translations', function (User $user) {
    return $user->hasRole('admin');
});
```

أو باستخدام وسيط الدور مباشرةً:

```php
'middleware' => ['web', 'auth', 'role:admin'],
```

::: danger لا تترك الوسيط كـ `['web']`
إذا أزلت `'auth'` من المصفوفة، تُصبح جميع صفحات إدارة Lingua
متاحة للعموم بدون مصادقة. افعل ذلك فقط في بيئات التطوير المحلية
المعزولة بالكامل.
:::

## حماية XSS (F1)

عند حفظ ترجمة من النوع `html`، تمر القيمة عبر `HtmlSanitizer` قبل
كتابتها إلى قاعدة البيانات:

- **الوسوم المسموح بها:** `<a>`، `<b>`، `<strong>`، `<i>`، `<em>`، `<u>`، `<s>`، `<del>`، `<br>`، `<p>`، `<ul>`، `<ol>`، `<li>`، `<blockquote>`، `<code>`، `<pre>`، `<span>`
- **السمات المسموح بها:** `href`، `target`، `rel`، `class`، `id`
- **مُمنوعة:** `<script>`، `<iframe>`، معالجات `on*`، `javascript:` في `href`

ترجمات `text` و`markdown` لا تُعقَّم بـ `HtmlSanitizer` — تأكد
من الهروب المناسب عند العرض إذا لزم الأمر.

---

## حماية حقن SQL (F2)

`LinguaManager` يرفض الاستعلامات التي تحتوي على دوال JSON المخصصة
لقاعدة البيانات (`JSON_KEYS` في MySQL، `json_object_keys` في PostgreSQL،
`OPENJSON` في SQL Server). هذا يمنع هجمات الحقن التي تستهدف سحب
الترجمات عبر بنية قاعدة بيانات JSON.

---

## حماية من اجتياز المسارات (F3)

عندما تقرأ Lingua الترجمات من ملفات `lang/` أو تكتب إليها (محرك `file`
أو أثناء المزامنة)، يُتحقق من كل مسار ملف:

```php
// Any path outside lang_dir is rejected
PathGuard::assertSafe($resolvedPath, config('lingua.lang_dir'));
```

هجمات اجتياز المسارات (`../../etc/passwd`) تُرفض بـ
`PathTraversalException`.

---

## حماية من إعادة التوجيه المفتوحة {#open-redirect-protection}

عندما يبدِّل المستخدم اللغة، تُعيد Lingua تحميل **الصفحة الحالية** عبر:

1. قراءة `Request::getRequestUri()` للحصول على المسار الكامل
2. التحقق من أن المسار يبدأ بـ `/` (مسار محلي فقط)
3. رفض أي رابط يحتوي على `://` (URL مطلق)

هذا يمنع إعادة التوجيه المفتوحة عبر معامل `?redirect=` المُصطنَع.

## أمان أصول الواجهة

أصول Lingua (CSS) تُقدَّم عبر مسار `lingua.assets` بدلاً من
ملفات مُنشورة. هذا يعني:

- لا توجد ملفات CSS/JS في مجلد `public/vendor/lingua`
- الأصول تُعاد فقط عند الطلب عبر مسار الحزمة
- الـ versioning أتوماتيكي — لا `cache bust` يدوي

---

## أمان محرك الملفات (F3 الممتد)

عند استخدام محرك `file`، تُطبِّق Lingua قيوداً إضافية:

- يُعقَّم مسار كل ملف ويُتحقق منه مقابل `lang_dir`
- يُستخدم `AtomicFileWriter` للكتابة — يكتب إلى ملف مؤقت أولاً ثم
  يُغيِّر الاسم بشكل ذري
- `opcache_invalidate($path, true)` يُستدعى بعد كل كتابة لإبطال
  الشيفرة المترجمة المخزَّنة مؤقتاً

---

## الحماية من حقن الصيغ (F6 الممتد)

عند الاستيراد، يُرفض أي مفتاح أو قيمة يبدأ بـ `=`، `+`، `-`، أو `@`
(أحرف بدء صيغ Excel/LibreOffice) لمنع هجمات حقن الصيغ في ملفات CSV.

---

## قائمة التحقق للإنتاج

- [ ] `middleware` تحتوي على `'auth'` أو قيود أقوى
- [ ] `LINGUA_GATE` مضبوط إذا لزمت صلاحيات ضيِّقة بالأدوار
- [ ] لا أحد في الفريق يملك بيانات اعتماد قاعدة بيانات مباشرة لـ
      `language_lines` — استخدام الواجهة فقط
- [ ] `lang_dir` نقطة إلى مجلد `lang/` الحقيقي
- [ ] تُسجَّل نتائج التدقيق (`audit:log` إذا توفَّر)
- [ ] مراجعة ترجمات `html` بشكل دوري
