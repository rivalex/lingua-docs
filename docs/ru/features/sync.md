# Двунаправленная синхронизация

Lingua может импортировать переводы из локальных файлов в базу данных и экспортировать
обратно — давая лучшее из обоих миров: **runtime на основе БД** и **версионный контроль через файлы**.

## Два направления

```
lang/en/*.php        ──┐
lang/en.json           │  lingua:sync-to-database ──►  language_lines (DB)
lang/it/*.php          │
lang/it.json           │
lang/vendor/…          │  ◄── lingua:sync-to-local
                      ─┘
```

## Синхронизация в базу данных

Импортирует все файлы `lang/` в таблицу `language_lines`.

```bash
php artisan lingua:sync-to-database
```

### Что импортируется

- `lang/{locale}/*.php` — стандартные PHP-файлы переводов
- `lang/{locale}.json` — JSON-файлы переводов
- `lang/vendor/{package}/{locale}/*.php` — переводы пакетов

### Поведение upsert

Lingua использует `updateOrCreate` с сопоставлением по `group` + `key`:

- **Новые ключи** — вставляются
- **Существующие ключи** — значения локалей **сливаются** в JSON-столбец; редактированные значения из UI **сохраняются**
- **Автоопределение типа** запускается для назначения `text` / `html` / `markdown`

### Автоопределение типа

| Правило | Тип |
|---|---|
| Строка содержит HTML-теги (`<…>`) | `html` |
| Строка парсится как Markdown | `markdown` |
| Иначе | `text` |

::: tip
Тип консервативен — `html` или `markdown` только при явном соответствии. Можно изменить вручную через UI.
:::

### Через фасад

```php
use Rivalex\Lingua\Facades\Lingua;

Lingua::syncToDatabase();
```

## Синхронизация в локальные файлы

Экспортирует все переводы из `language_lines` обратно в PHP и JSON файлы `lang/`.

```bash
php artisan lingua:sync-to-local
```

### Что экспортируется

- Не-vendor переводы → `lang/{locale}/{group}.php`
- JSON-группа (`single`) → `lang/{locale}.json`
- Переводы пакетов → `lang/vendor/{vendor}/{locale}/{group}.php`

### Сценарии использования

- **Версионный контроль** — коммитьте файлы для отслеживания изменений
- **CI/CD** — экспортируйте перед деплоем, если инструменты ожидают файловые переводы
- **Резервные копии** — точечные снимки всех переводов

### Через фасад

```php
Lingua::syncToLocal();
```

## Обновление из встроенного набора данных <Badge type="warning" text="Изменено в 2.0" />

Загружает последние строки переводов из встроенного набора данных Lingua и синхронизирует
в базу данных. В 2.0 **нет зависимости от laravel-lang** — данные поставляются внутри пакета.

```bash
php artisan lingua:update-lang
```

::: tip Изменено в 2.0
Команда больше не вызывает `lang:update` из `laravel-lang/common`. Она обновляет
строки из встроенного набора данных (26 локалей × 7 групп, Laravel v13.14.0).
:::

---

## Точечное кеширование <Badge type="warning" text="Изменено в 2.0" />

В database-режиме Lingua **точечно** сбрасывает кеш по `(locale, group)` после
каждой операции синхронизации. Нет глобального `cache:clear` ни в одном пути
синхронизации. Ключ кеша: `lingua.trans.{locale}.{group}`.

## Автоматизированные рабочие процессы

### При деплое

```bash
php artisan lingua:sync-to-database
php artisan optimize:clear
```

### Через планировщик

```php
// routes/console.php
Schedule::command('lingua:sync-to-database')->hourly();
```

### После установки нового пакета

```bash
php artisan lingua:sync-to-database
```

## Советы

::: tip Считайте БД источником истины
Синхронизируйте в файлы только когда нужен версионный контроль. Избегайте прямого
редактирования локальных файлов пока БД активна — следующий `sync-to-database`
перезапишет правки у существующих ключей.
:::

::: tip Полный цикл реорганизации
1. `lingua:sync-to-local` — экспортировать всё
2. Отредактировать файлы на диске
3. `lingua:sync-to-database` — повторно импортировать
:::
