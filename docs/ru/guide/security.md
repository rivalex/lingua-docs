# Безопасность

Lingua 2.0 прошла комплексное укрепление безопасности и **безопасна по умолчанию**.
На этой странице описаны имеющиеся средства защиты и действия, которые необходимо
предпринять для обеспечения безопасности вашего деплоя.

::: tip Безопасность по умолчанию
Интерфейс управления поставляется за middleware `['web', 'auth']`, ресурсы
обслуживаются через realpath-jail, а входные данные переводов санируются. Вы
*включаете* расширенный доступ, а не отключаете защиту.
:::

## Комплекс мер безопасности v2.0 (F1–F9)

| ID | Название | От чего защищает | Как | Файл |
|---|---|---|---|---|
| F1 | Защита от DoS кеша | Неограниченный рост кеша из произвольных строк локалей | Валидация локали через regex перед `rememberForever` | `src/Database/DatabaseRepository.php` |
| F2 | Запрет SQL-инъекций | Инъекция через JSON SQL-функции | JSON SQL-функции удалены; все агрегации выполняются в PHP | `src/Database/DatabaseRepository.php` |
| F3 | Защита от path traversal | Выход за пределы директории переводов | `PathGuard::assertSafeSegment()` | `src/Support/PathGuard.php`, `src/Locales/BundledTranslationSource.php` |
| F4 | Загрязнение локали / инъекция имени файла | Запись в незарегистрированные локали; вредоносные имена файлов для скачивания | Прерывание с кодом 422 для незарегистрированной целевой локали; санированный `Content-Disposition` | `src/Livewire/Import.php`, `src/Http/Controllers/TransferExportController.php` |
| F5 | Защита вендорных переводов | Удаление защищённых вендорных строк | `VendorTranslationProtectedException` при вызове `forgetTranslation()` для вендорных строк | `src/Exceptions/VendorTranslationProtectedException.php`, оба репозитория |
| F6 | Отклонение wildcard-ключей | Массовое присвоение через wildcard-ключи | Отклонение `*` / `\0` в идентификаторе импорта | `src/Transfer/RowMapper.php` |
| F7 | Ограничение ReDoS | Катастрофическое обратное отслеживание при определении типа | Более строгий regex типа (`\[[^\]]+\]`); пропуск regex для строк длиннее 10000 символов | `src/Livewire/Translation/Row.php` |
| F8 | Нераскрытие информации об ошибках | Утечка внутренних данных в UI | Обобщённая локализованная ошибка в UI; детали в `Log::error` | `src/Livewire/Import.php` |
| F9 | Auth gate | Несанкционированный доступ к admin-маршрутам | Middleware `can:{gate}` добавляется при установке `LINGUA_GATE` | `routes/web.php`, `config/lingua.php` |

## Защита от XSS

HTML-переводы санируются `HtmlSanitizer`
(`src/Support/HtmlSanitizer.php`) перед хранением и рендерингом:

- DOM-парсинг с **белым списком атрибутов для каждого тега**
- Валидация URI — допускаются только схемы `http`, `https` и `mailto`
- Удаление управляющих символов (нейтрализует такие трюки как `java\tscript:`)

Хранимый XSS ограничен только типом `html`; переводы типа `text` всегда экранируются.

## Аутентификация

Маршруты управления по умолчанию используют `['web', 'auth']`. Для доступа на основе ролей
установите gate авторизации:

```env
LINGUA_GATE=manage-translations
```

```php
use App\Models\User;
use Illuminate\Support\Facades\Gate;

Gate::define('manage-translations', fn (User $u) => $u->hasRole('admin'));
```

Lingua добавляет `can:manage-translations` к своим admin-маршрутам. Также можно
напрямую отредактировать массив `middleware` (см.
[Конфигурация](/ru/guide/configuration#security-access)).

## Защита от открытых редиректов

Когда пользователь переключает локаль, Lingua перезагружает **текущую** страницу.
Цель извлекается из `ManagesLocale::getRequestUri()` и проверяется
**regex-guard на локальный путь**, поэтому злоумышленник не может передать абсолютный
URL в редирект.

## Безопасность ресурсов

Скомпилированные CSS/JS Lingua обслуживаются маршрутом `lingua.assets`, который
разрешает запрашиваемый файл через **realpath-jail** — запросы, разрешающиеся
за пределами директории ресурсов пакета, отклоняются. Маршрут ресурсов находится
**за пределами** аутентифицированной группы маршрутов, поэтому стили загружаются
на экранах входа.

## Безопасность в режиме file

В [драйвере хранилища `file`](/ru/guide/storage) правки UI записываются через
`AtomicFileWriter` (`src/Support/AtomicFileWriter.php`):

- Запись во временный файл с последующим **атомарным переименованием** на место, чтобы
  параллельный запрос никогда не читал наполовину записанный файл
- Вызов `opcache_invalidate($path, true)` после переименования, чтобы новый байткод
  применялся в рамках того же запроса

## Защита от формульных инъекций

Экспортируемые и импортируемые ячейки таблиц, начинающиеся с `=`, `+`, `-`,
`@`, символа табуляции или возврата каретки, получают префикс в виде одинарной кавычки (`'`)
для нейтрализации формульных инъекций в CSV/таблицах.

## Более ранние исправления (v1.1.x)

В ветке 1.1.x были выпущены дополнительные исправления, которые перенесены в 2.0:

- **3 CRITICAL** — path traversal в маршруте ресурсов (realpath jail), SQL-инъекция
  через locale-in-JSON, обход аутентификации (middleware `auth` по умолчанию)
- **2 HIGH** — открытый редирект при переключении локали, хранимый XSS ограничен типом `html`
- **5 MEDIUM** — инъекция аргументов Artisan (переход на форму массива), TypeError при null `Language`,
  ограничение `$perPage` (≤ 100) и связанная валидация ввода
- **4 LOW** — разрозненные исправления укрепления и раскрытия данных

## Чеклист безопасности

- [ ] Сохраняйте middleware `['web', 'auth']` по умолчанию (или более строгий)
- [ ] Установите `LINGUA_GATE` для доступа на основе ролей в многопользовательских приложениях
- [ ] Используйте тип `html` только для доверенного контента; предпочитайте `text` в остальных случаях
- [ ] В режиме file убедитесь, что деплои не открывают пути записи `lang/` для
      ненадёжных пользователей
- [ ] Обновляйте Lingua для получения исправлений безопасности
